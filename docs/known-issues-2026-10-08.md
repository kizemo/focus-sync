## BUG-1 ★ 注入逃逸到非对话框窗口,并自动触发回车 —— ✅ 已修复(待验证)

**严重度:高(安全)** —— 它能向任意前台应用输入文本并触发回车键。
**修复时间**:2026-10-08 13:30

### 现象(用户直接观察,非日志推断)

> 在弹出窗口中,不仅地址栏会填入 sigma 激活的路径……甚至会扩展到其他非弹出窗口,
> 比如我们当前的会话,在切换过来后,刚才就自动填入了路径并且回车发送了

即:焦点切到聊天窗口后,路径被自动输入并**回车发送**。

### 推断的机理(尚未用日志直接证实)

```
T0  monitor 检测到前台 HWND 是 #32770 文件对话框 → 发出 DialogEvent::Opened
T0+ main 收到事件,开始 UIA 扫描 best_edit / best_button(实测耗时 ~300ms)
T0+200ms  用户切换到另一个应用(聊天窗口)→ 前台变了
T0+300ms  H1 执行 SendInput:Ctrl+L → 路径 → Enter
          ★ SendInput 永远发给「发送那一刻的前台窗口」,而不是对话框
```

**现有两道护栏为何没拦住:**

| 护栏 | 检查内容 | 为何漏掉 |
|---|---|---|
| 护栏 1 | 文件名框读回,判断路径是否落进了文件名框 | 焦点在**别的进程**时,对话框的文件名框根本没变 → 判定「安全」→ 放行 Enter |
| 护栏 2 | `GetGUIThreadInfo` 查前台线程的焦点控件 automation_id | 只查「焦点在不在 1001 文件名框」,**没有校验这个前台窗口是不是那个对话框** |

**缺失的检查**:SendInput 之前,必须确认**当前前台 HWND 仍等于目标对话框 HWND**,
而且必须**在发送的同一时刻**验证(而不是 300ms 前)。

### ✅ 修复内容(v0.5.7 BUG-1)

新增 `uia_inject.rs::dialog_still_foreground(state, dialog_hwnd)`,在**两个**
`SendInput` 调用点前**各校验一次**:

```
UIA 扫描 ~300ms
  ↓
[闸门 1] dialog_still_foreground?  ← 不通过则一个按键都不发,return false
  ↓
SendInput 批次1(Ctrl+L / End / Back×128 / 路径)
  ↓
80ms sleep + 两道原有护栏
  ↓
[闸门 2] dialog_still_foreground?  ← 不通过则跳过 Enter,return true
  ↓
SendInput 批次2(Enter)
```

校验内容两条,同时满足:
1. `IsWindow(hwnd)` —— 对话框没被销毁(句柄可能被复用)
2. `state.foreground_dialog() == hwnd` —— monitor 发布的值,每次轮询刷新(≤8ms 新鲜度)

**刻意不使用 `GetForegroundWindow()`**:本代码跑在无消息泵的 HTTP 线程上,
该调用返回过与 monitor 矛盾的值(见 F-1 记录)。

**返回值的语义选择**:
- 闸门 1 不过 → `return false` → 不发任何按键,交回 H2 回退
- 闸门 2 不过 → `return true` → 地址栏已填好,**不**落回 H2
  (否则会往用户已不再注视的对话框的文件名框里写东西)

**验证清单(修复后待确认)**:
- [ ] 在 Sigma FM 切目录后**立刻**切到聊天窗口 → 聊天窗口**不得**收到任何输入
- [ ] 日志出现 `ABORTING before dispatching any keys (BUG-1)` 或
      `SKIPPING Enter (BUG-1)` —— 说明闸门确实拦下了一次
- [ ] 地址栏导航仍然生效(不能为了修 BUG-1 把功能整体关掉)

## BUG-2 文件名框被写入「路径片段 + 原文件名」

**严重度:高** —— 直接污染用户输入,且是 BUG-3 的成因。

### 现象(截图 + 日志双重证实)

日志 `spike.log`:
```
13:10:48  Read  path='线上培训\第4次线上培训纪要_2026-10-08'
13:10:48  dialog path='线上培训\第4次线上培训纪要_2026-10-08'
          current='E:\办公文件\02 1号位\线上培训\第4次线上培训_2026-10-08'; writing current
13:10:49  Write target=E:\办公文件\02 1号位\线上培训\第4次线上培训_2026-10-08
```

截图文件名框内容:`线上培训\第4次线上培训纪要_2026-10-08`

### 读出来的信息

| 片段 | 来源 |
|---|---|
| `线上培训\` | **目标路径的尾部片段**(来自 `E:\办公文件\02 1号位\线上培训\...`) |
| `第4次线上培训纪要_2026-10-08` | **用户自己的原文件名**(目标路径里是 `第4次线上培训_2026-10-08`,没有「纪要」) |

⇒ 路径写入只**部分**发生,且原文件名被还原时没有清干净。

### 推断的机理

H1 失败后回退到 H2(向文件名框 `SetValue(target_path)` → 50ms → `SetValue(original)`)。
本例中还原不完整 —— 可能是:
- H2 的第二次 `SetValue` 与对话框自身的输入处理竞争
- 或 H1 的按键串有一部分落进了对话框,随后 H2 又叠加
- 或窗口在注入过程中重建(`13:10:47`、`13:10:53` 连续出现
  `UIA error: 0x80004005 未指定的错误`,说明对话框 HWND 在抖动)

## BUG-3 确认保存时报「路径不存在」,但目录确实存在

**严重度:中**(是 BUG-2 的下游表现,不是独立问题)

### 现象(截图)

文件名框内容被改成 `线上培训\第4次线上培训纪要_2026-10-08` 后点「保存」,Windows 弹出:

```
线上培训\第4次线上培训纪要_2026-10-08
路径不存在。
请检查路径是否正确，然后重试。
```

### 成因

对话框当前目录已经是 `E:\办公文件\02 1号位\线上培训\第4次线上培训_2026-10-08`(地址栏正确),
但文件名框里带着 `线上培训\` 前缀。Windows 把 `线上培训\第4次线上培训纪要_2026-10-08`
当作**相对路径**去解析,自然找不到。

⇒ **修好 BUG-2,BUG-3 自动消失。**

## 三者的关系

```
        monitor 检测到前台是对话框(300ms 之前)
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
   用户期间切到别的应用      用户一直留在对话框
        │                       │
        ▼                       ▼
  【BUG-1】SendInput 打到     【BUG-2】H2 回退写文件名框
  别的进程并回车发送          只写进部分路径
        │                       │
   危害:向任意应用发消息       ▼
                            【BUG-3】文件名框带路径前缀
                                        ▼
                                   「路径不存在」报错
```

**BUG-1 与 BUG-2 共享同一个前置条件:注入动作跨越了一个焦点可能变化的时间窗口,
却没有在动作发生的当下确认「前台仍是目标对话框」。**

---

## 修复方向(待实施,尚未动手)

1. **发送前瞬时校验**:在 `SendInput` 之前**立即**(不是 300ms 前)调用
   `GetForegroundWindow()`,确认仍等于目标对话框 HWND;不等则整体放弃本次注入。
   这一条同时消除 BUG-1 和 BUG-2 的触发条件。
2. **H2 的自验证**:写入后必须读回文件名框,确认它等于**原始文件名**(完全相等,
   而非「不包含路径」),不相等则主动清空重写。
3. **对话框抖动处理**:`UIA error 0x80004005` 连续出现说明 HWND 在重建,
   应在检测到此类错误时放弃本次写入并等待下一个稳定窗口。
